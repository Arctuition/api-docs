`GET https://api.arcsite.com/v1/projects`

### Query Parameters

| Parameter        | Default | In    | Description                                                                                                        |
| ---------------- | ------- | ----- | ------------------------------------------------------------------------------------------------------------------ |
| page             | 1       | query | Request a specific page                                                                                            |
| per_page         | 10      | query | Page size (maximum 100)                                                                                            |
| created_at_begin | None    | query | (optional) Only return projects created at or after this time, in UTC ISO 8601 format (e.g., `2025-01-16T04:19:23`) |
| created_at_end   | None    | query | (optional) Only return projects created at or before this time, in UTC ISO 8601 format (e.g., `2025-01-16T04:19:23`) |

:::note
Send `created_at_begin` and `created_at_end` in UTC. A timezone offset in the value is ignored, not converted. A date without a time (e.g., `2025-01-16`) means `00:00:00` on that day, so `created_at_end=2025-01-16` excludes the rest of January 16.
:::

| ------------------ | ------------ | ---------------------------------------------- |

| customer           | Customer     | (optional) Customer profile of the project     |

Tags are case-sensitive. Tags that don't exist yet are created in your organization. Responses list tags in alphabetical order.
:::

### Project Integrations

ArcSite supports integration with various external platforms. Once project creation is complete, you can use the standard integration solutions we provide for different platforms to integrate your project. After integration is completed, your project will gain additional functionality to support data synchronization and interactions with third-party platforms. For specific details, see the integrations module.

### Project Name Rules

1. Project name must be unique across the same organization.
2. Project name cannot contain any of the following characters: `:` `/` `\`.
3. Project name cannot start with `.`.
4. Project name must be less than or equal to 200 characters.

[Create Project](#create-project) adjusts a name that breaks rules 2–4 instead of rejecting it: `:` `/` `\` become spaces, a leading `.` is removed, the name is cut to 200 characters, and surrounding whitespace is trimmed. Use the `name` in the response as the stored name. [Update Project](#update-project) rejects such a name with `400`.

If your organization already has a project with the same name, the request returns `400 Bad Request`:

```json title="Duplicate name response"
{
  "message": "Project name Backyard Fence already exists, please use another name."
}
```

Other invalid requests, such as a missing required field, also return `400`.

`customer`, `customer.address` and `work_site_address` are replaced as a whole: any sub-field you leave out of an object you send is cleared. :::

:::note
If `tags` is provided, the tags of the project will be replaced by the new provided tags. If the value of `tags` is set to `[]`, all existing tags on the project will be removed.
:::

The response is the updated project, in the same format as the [Create Project](#create-project) response.

### Collaborator Entry

Each entry is either a user or a user group, distinguished by `type`:

| Field    | Type          | Description                                                                     |
| -------- | ------------- | ------------------------------------------------------------------------------- |
| type     | String        | `user` or `group`                                                               |
| email    | String        | (user only) Email of the collaborator                                           |
| group_id | String        | (group only) Id of the user group, see [Get User Group](#get-user-group)        |
| name     | String        | (group only) Name of the user group                                             |
| role     | [Role](#role) | Project role of the user, or of every member of the group. Same values as accepted by [Add Project Collaborators](#add-project-collaborators). |

:::note
Groups are not expanded here — a shared group appears as a single `group` entry. Use [Get User Group](#get-user-group) with the `group_id` to list its members.
:::

## Add Project Collaborators

Adds collaborators to a project. Successfully added collaborators are in the `success_items` field of the response, and failed items are in `fail_items`. This API is idempotent, so the same collaborator can be added multiple times. Adding an existing collaborator with a different role adds that role; it doesn't replace the current one. To lower a collaborator's role, remove them and add them again.

`POST https://api.arcsite.com/v1/projects/<id>/add_collaborators`

<Tabs syncKey="lang">
<TabItem label="cURL">

```shell
curl -X POST 'https://api.arcsite.com/v1/projects/<ID>/add_collaborators' \
  -H 'Authorization: Bearer your_api_token_here' \
  -H 'Content-Type: application/json' \
  -d '{
    "collaborators": [
      { "email": "dev@example.com", "role": "PROJECT_ADMIN" },
      { "email": "unknown@example.com", "role": "PROJECT_ADMIN" }
    ]
  }'
```

</TabItem>

### Role

1. `PROJECT_ADMIN` — Project admins have full access to the project.
2. `PROJECT_COLLABORATOR` — Can create, edit, and delete drawings. This role cannot delete the project or manage collaborators.

## Import PDF

Your uploaded PDF will be split into multiple pages; one ArcSite drawing is created for each page.

`POST https://api.arcsite.com/v1/projects/<id>/import_pdf`

<Tabs syncKey="lang">
<TabItem label="cURL">

```shell
# upload a local file
curl --location 'https://api.arcsite.com/v1/projects/<ID>/import_pdf' \
  -H "Authorization: Bearer your_api_token_here" \
  --form 'file=@"/<file_path>/<file_name.pdf>"'

# or pass the file url directly
curl --location 'https://api.arcsite.com/v1/projects/<ID>/import_pdf' \
  -H "Authorization: Bearer your_api_token_here" \
  --form 'file_url="https://example.com/plan.pdf"'
```

</TabItem>
<TabItem label="JavaScript">

```js
// upload a local file
const form = new FormData();
form.append("file", fileInput.files[0]);

// or pass a file URL directly:
// form.append("file_url", "https://example.com/plan.pdf");

const response = await fetch("https://api.arcsite.com/v1/projects/<ID>/import_pdf", {
  method: "POST",
  headers: {
    Authorization: "Bearer your_api_token_here",
  },
  body: form,
});
const data = await response.json();
```

</TabItem>
<TabItem label="Python">

```python

    response = requests.post(
        "https://api.arcsite.com/v1/projects/<ID>/import_pdf",
        headers={"Authorization": "Bearer your_api_token_here"},
        files={"file": f},
    )

# or pass a file URL directly (still sent as multipart/form-data):
# response = requests.post(
#     "https://api.arcsite.com/v1/projects/<ID>/import_pdf",
#     headers={"Authorization": "Bearer your_api_token_here"},
#     files={"file_url": (None, "https://example.com/plan.pdf")},
# )
data = response.json()
```

</TabItem>
</Tabs>

```json title="Response"
{
  "drawings": [
    {
      "id": "36029621653385418"
    },
    {
      "id": "36029621653385407"
    }
  ]
}
```

### Request Payload

| Parameter | In   | Description                                  |
| --------- | ---- | -------------------------------------------- |
| file      | Body | The binary PDF file to be uploaded           |
| file_url  | Body | The URL of a publicly accessible PDF file    |

:::note
Request content type must be `multipart/form-data` to upload a PDF file, also when you send `file_url`. Either `file` or `file_url` must be provided, but not both.
:::

`file_url` must be an `https` URL on the public internet that returns the PDF directly: redirects and credentials in the URL aren't allowed, the file can be at most 100 MB, and the server must respond within 20 seconds.

The request is processed synchronously, so it can take a while for large PDFs. A page that fails to process is skipped, so `drawings` can have fewer entries than the PDF has pages.

Errors: `400` when `file` and `file_url` are both missing or both present, when the URL can't be downloaded, or when the file isn't a valid PDF (including corrupted and password-protected files). `403` when your organization has reached its limit of drawings created from PDF files.

### Parameters
