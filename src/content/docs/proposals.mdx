## Query Proposal Templates

Returns the published PDF proposal templates of your organization, most recently updated first.

`GET https://api.arcsite.com/v1/proposal_templates`

<Tabs syncKey="lang">
<TabItem label="cURL">

```shell
curl "https://api.arcsite.com/v1/proposal_templates" \
  -H "Authorization: Bearer your_api_token_here"
```

</TabItem>
<TabItem label="JavaScript">

```js
const response = await fetch("https://api.arcsite.com/v1/proposal_templates", {
  headers: {
    Authorization: "Bearer your_api_token_here",
  },
});
const data = await response.json();
```

</TabItem>
<TabItem label="Python">

```python
import requests

response = requests.get(
    "https://api.arcsite.com/v1/proposal_templates",
    headers={"Authorization": "Bearer your_api_token_here"},
)
data = response.json()
```

</TabItem>
</Tabs>

```json title="Response"
[
  {
    "id": "36029621652695041",
    "name": "Proposal Template 1"
  }
]
```

### Query Parameters

| Parameter | Default | In    | Description             |
| --------- | ------- | ----- | ----------------------- |
| page      | 1       | query | Request a specific page |
| per_page  | 10      | query | Page size (maximum 100) |

## Query Proposals

Returns a list of proposals of your organization. You can filter by project and paginate; proposals are sorted by most recent activity first. For a change order chain, only the latest version is returned; see [Change Orders](#change-orders).

`GET https://api.arcsite.com/v1/proposals`

<Tabs syncKey="lang">
<TabItem label="cURL">

```shell

  -H "Authorization: Bearer your_api_token_here"
```

```js
const response = await fetch("https://api.arcsite.com/v1/proposals", {
```

### Query Parameters

| Parameter  | Default | In    | Description                                |
| ---------- | ------- | ----- | ------------------------------------------ |
| project_id | -       | query | (optional) Project ID to filter proposals. |
| page       | 1       | query | (optional) Request a specific page.        |
| per_page   | 10      | query | (optional) Page size (maximum 100).        |

### Proposal

Each item in the response array is a `Proposal` object with the following fields. Some fields are returned only for specific statuses.

| Parameter            | Type           | Description                                                                          |
| -------------------- | -------------- | ------------------------------------------------------------------------------------ |
| proposal_id          | String         | Proposal ID                                                                          |
| project_id           | String         | Project ID the proposal belongs to                                                   |
| name                 | String         | Proposal name                                                                        |
| status               | String         | Proposal status. See the status values below.                                        |
| sales_representative | String         | Name of the sales representative                                                     |
| contact_email        | String         | Email of the sales representative                                                    |
| customer_name        | String         | Customer name                                                                        |
| customer_email       | String \| null | Customer email                                                                       |
| document_number      | String \| null | Proposal document number                                                             |
| template_id          | String \| null | Proposal template ID; `null` when the proposal is signed in app                      |
| close_note           | String         | (optional) Reason for closing the proposal. Present when status is `VOID` or `LOST`. |
| total                | Number         | (optional) Total amount of the proposal. Present once the proposal is approved: status is `APPROVED`, `PARTIALLY_PAID`, `PAID` or `OVER_PAID`. For a change order, this is the full revised amount; see [Change Orders](#change-orders). |
| pdf_url              | String         | (optional) URL of the proposal PDF file. Present once the proposal is approved.      |
| approved_option      | ApprovedOption | (optional) Approved option information. Present once the proposal is approved.       |
| initial_proposal_id  | String         | (optional) ID of the first proposal in the change-order chain. Present on every proposal in a chain, including the original proposal, where it equals `proposal_id`. |

### ApprovedOption

| Parameter          | Type   | Description                                                               |
| ------------------ | ------ | ------------------------------------------------------------------------- |
| id                 | String | (optional) ID of the approved option, only for online approvals.          |
| drawing_id         | String | ID of the associated drawing resource.                                    |
| drawing_version_id | String | (optional) ID of the approved drawing version, only for online approvals. |

:::note
The status field is an enum with the following values:

- `DRAFT`: When a new proposal is created
- `PENDING`: When a proposal is sent to the customer
- `ESIGNED_BY_CLIENT`: When the customer has e-signed the proposal and it is waiting for the sales representative to counter-sign
- `APPROVED`: When a proposal is approved or e-signed (including approvals captured in the app)
- `PARTIALLY_PAID`: When an approved proposal has received part of its payment
- `PAID`: When an approved proposal has been paid in full
- `OVER_PAID`: When the payments received exceed the proposal total
- `VOID`: When a proposal is marked as void
- `LOST`: When a proposal is marked as lost
- `EXPIRED`: When a sent proposal passes its expiration date without being approved

Once a payment is received, an approved proposal reports `PARTIALLY_PAID` or `PAID` instead of `APPROVED`.
:::

:::note
The `pdf_url` field is typically a time-limited URL for 24 hours. You should download the PDF soon after retrieving it.
:::

## Get Proposal by ID

Returns one proposal by proposal ID. Returns `404` (`Proposal not found`) if the proposal doesn't exist in your organization. The response uses the same base `Proposal` fields as [Query Proposals](#query-proposals). For online proposals, the response also includes `proposal_options`, which can be used to link unsold proposals to the drawing versions they were generated from.

`GET https://api.arcsite.com/v1/proposals/<proposal_id>`

<Tabs syncKey="lang">
<TabItem label="cURL">

```shell
curl "https://api.arcsite.com/v1/proposals/<proposal_id>" \
  -H "Authorization: Bearer your_api_token_here"
```

</TabItem>

```js
const response = await fetch("https://api.arcsite.com/v1/proposals/<proposal_id>", {
```


### Parameters

| Parameter   | Type   | Description           |
| ----------- | ------ | --------------------- |
| proposal_id | String | (required) Proposal ID |

### Query Parameters

| Parameter          | Default | In    | Description                                                       |
| ------------------ | ------- | ----- | ----------------------------------------------------------------- |
| include_short_link | false   | query | (optional) Set to `true` to include `short_link` in the response. |

### Response Schema

The response is a `Proposal` object with the fields documented in the [Proposal](#proposal) schema. Online proposals also include the following field:

| Parameter        | Type                 | Description                                                                                     |
| ---------------- | -------------------- | ----------------------------------------------------------------------------------------------- |
| proposal_options | List[ProposalOption] | (optional) Full list of proposal options for online proposals, including drawing and PDF details |

When `include_short_link` is `true`, the response also includes the following field:

| Parameter  | Type   | Description                                                                                                                                                                  |
| ---------- | ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| short_link | String | The link the customer opens to view and sign the proposal, the same one as Copy Short Link in ArcSite. `null` while the proposal is in `DRAFT`. Doesn't change once created. |

### ProposalOption

| Parameter          | Type   | Description                                              |
| ------------------ | ------ | -------------------------------------------------------- |
| id                 | String | ID of this proposal option                               |
| name               | String | Proposal option name                                     |
| drawing_id         | String | ID of the drawing resource used to generate this option  |
| drawing_version_id | String | ID of the drawing version used to generate this option   |
| total              | Number | Total amount for this proposal option                    |
| pdf_url            | String | Time-limited URL of the proposal option PDF file         |

:::note
For pending or draft online proposals, the top-level `approved_option` and `pdf_url` fields are not returned. Use `proposal_options` to access the drawing IDs and option PDF URLs.
:::

For an approved online proposal, match `approved_option.id` to `proposal_options[].id` to identify the approved option. Different options can share a `drawing_id`, so the drawing ID alone does not identify the approved option.

```js
const approvedOption = data.proposal_options.find(
  (option) => option.id === data.approved_option.id,
);
```

## Export Proposal PDF

Generates a proposal PDF for the latest version of a drawing using the given proposal template, and returns a temporary download URL. The PDF is generated synchronously.

`POST https://api.arcsite.com/v1/export_proposal_pdf`

<Tabs syncKey="lang">
<TabItem label="cURL">

```shell
curl -X POST "https://api.arcsite.com/v1/export_proposal_pdf" \
  -H "Authorization: Bearer your_api_token_here" \
  -H "Content-Type: application/json" \
  -d '{"drawing_id": "your_drawing_id", "template_id": "36029621652695041"}'
```

</TabItem>
<TabItem label="JavaScript">

```js
const response = await fetch("https://api.arcsite.com/v1/export_proposal_pdf", {
  method: "POST",
  headers: {
    Authorization: "Bearer your_api_token_here",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    drawing_id: "your_drawing_id",
    template_id: "36029621652695041",
  }),
});
const data = await response.json();
```

</TabItem>
<TabItem label="Python">

```python
import requests

response = requests.post(
    "https://api.arcsite.com/v1/export_proposal_pdf",
    headers={"Authorization": "Bearer your_api_token_here"},
    json={"drawing_id": "your_drawing_id", "template_id": "36029621652695041"},
)
data = response.json()
```

</TabItem>
</Tabs>

```json title="Response"
{
  "url": "https://files.example.com/exports/Drawing_1_Proposal.pdf?X-Amz-Expires=3600&X-Amz-Signature=EXAMPLE"
}
```

### Request Body

| Parameter     | Type   | Description                                                                                                                              |
| ------------- | ------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| drawing_id    | String | (required) Drawing id. The PDF is generated from the drawing's latest version.                                                           |
| template_id   | String | (optional) Template id from [Query proposal templates](#query-proposal-templates). Provide exactly one of `template_id` or `template_name`. |
| template_name | String | (optional) Exact name of a proposal template. If several templates have this name, the most recently updated one is used. Provide exactly one of `template_id` or `template_name`. |

:::note
The returned url expires 1 hour after the response. Download the PDF right away; the file is temporary.
:::

Errors: `400` for an invalid body, or when the drawing is missing required fields or data groups; `403` when the drawing belongs to another organization; `404` when the drawing or template isn't found.

## Get Proposal Payments

Returns the successful and returned payments for the proposal, including payments received on earlier versions of the proposal when it is a change order. Payments are sorted by creation time, oldest first. Failed, pending and fully canceled payments are not included. Returns `404` (`Proposal not found`) if the proposal doesn't exist in your organization.

`GET https://api.arcsite.com/v1/proposals/<proposal_id>/payments`

### Response Schema

The response is an array of Payment objects with the following fields:

| Field           | Type   | Description                                                                                                                                                  |
| --------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| paid_amount     | Number | The amount paid                                                                                                                                              |
| pay_channel     | String | Channel through which payment was received. Values: `arcsite_payment` or `mark_as_paid`                                                                      |
| paid_time       | String | Date and time (UTC) when payment was received, in ISO 8601 format without a timezone designator (e.g. `2025-11-06T10:15:30`). Present when `pay_channel` is `arcsite_payment` |
| paid_date       | String | Date when payment was recorded (YYYY-MM-DD format). Present when `pay_channel` is `mark_as_paid`                                                             |
| payment_method  | String | Method of payment. One of `Credit Card`, `ACH` (online payments), or `Check`, `Cash`, `Wire`, `Other` (marked as paid)                                        |
| status          | String | Payment status. Values: `succeeded` (payment successful) or `returned` (ACH Return occurred)                                                                 |
| refunded_amount | String | (optional) Amount refunded, as a decimal string such as `"500.00"`. Only included when greater than zero |
| canceled_amount | String | (optional) Part of this payment that was canceled in ArcSite (no money was moved), as a decimal string such as `"200.00"`. Only included when greater than zero |

Subtract `refunded_amount` and `canceled_amount` from `paid_amount` to get the amount applied to the proposal.

## Change Orders

A change order revises a proposal that has already been approved. ArcSite creates it as a new proposal in the same chain as the original, and it carries `initial_proposal_id`, the ID of the first proposal in the chain.

- The `total` of a change order is the full revised contract amount, not the amount added or removed. Use it in place of the earlier version's total; do not add the two together.
- Each new change order replaces the previous version. [Query Proposals](#query-proposals) returns only the latest version in each chain. Earlier versions are still available from [Get Proposal by ID](#get-proposal-by-id).
- A change order has no `total` until it is approved. Keep the amount of the last approved version until then.
- [Get Proposal Payments](#get-proposal-payments) for a change order includes the payments received on the earlier versions in its chain.
